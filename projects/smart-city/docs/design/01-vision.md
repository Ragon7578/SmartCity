# 智慧城市愿景 — 城市场景平台，内容可接入

## 核心判断

若把「人们生活的方方面面」都做成产品范围，愿景会过大、交付不可控。

城景要做的不是包办所有城市业务，而是：

1. **搭建平台**：同一张可互动城市场景 + 统一空间对象与接入约定。
2. **接入内容**：交通、停车、餐饮、物业、第三方业务等，以模块 / 贡献源方式挂入场景。
3. **先看见，再看见数据**：对象上图，状态与指标附着其上，一眼能懂。

「生活方方面面」是**平台可容纳的内容广度**，不是本期必须自建的功能清单。

## 产品名

**Urban Lens / 城景**

城市透镜平台：运营者看态势，接入方挂内容，市民侧能力由已接入内容自然形成。

## 平台 vs 内容

| 层级 | 职责 | 示例 |
|------|------|------|
| **平台** | 场景底图、空间对象模型、聚合与路由、状态视觉约定、模块接入契约 | gateway、city-scene、web 场景、统一 `id/module/x/y/status` |
| **内容（可插拔）** | 某一业务域的对象、指标、详情与互动 | traffic、parking、food；未来第三方或新微服务 |

已有与规划中的 parking / food / community 等，是**种子内容与示范接入**，用来验证平台，而不是「产品必须覆盖生活闭环」的承诺。

## 目标

| 目标 | 说明 |
|------|------|
| 空间共识 | 接入对象有稳定身份与位置，能画在同一张图上 |
| 一眼状态 | 颜色与动效先于表格说明问题 |
| 可接入 | 新内容按契约加入，不改无关模块、不拖垮旧模块 |
| 可替换 | 同一槽位可由自建服务或外部系统贡献，平台不绑死实现 |
| 可演示 | 用少量种子内容证明「接入 → 上图 → 看数」路径成立 |

## 非目标（近期）

- 自建覆盖全部生活领域的业务系统
- 完整物理级数字孪生仿真
- 闭环自动控制替人工决策
- 替代已有 SCADA / 专业 GIS 的系统账本地位
- 未接入契约稳定前，大规模铺开新业务域

## 原则栈

```
城市现实与各类内容源
    ↓ 接入契约（可视化贡献 / 详情路由 / 空间对象）
城景平台（场景 · 聚合 · 网关 · 状态表达）
    ↓
视觉呈现（位置、状态、趋势）
    ↓
行动（由具体内容模块提供：导航、派单、打卡等）
```

## 成功标准

- 新内容可按模块模板或贡献契约接入场景，并出现在聚合结果中
- 运营者能在已接入内容上，快速从场景识别异常片区
- 种子内容足够支撑一次端到端演示（例如停车 + 餐饮），不依赖「全能生活闭环」才算成功
- 未接入的领域在介绍口径中明确为「可接入」，而非「已具备」
