# 系统架构

## 总览

城景是 **城市场景平台** + **可插拔内容模块**（Spring Cloud 微服务 + 浏览器场景客户端）。

平台负责「能挂、能聚、能看」；各业务微服务是内容源，可增可减，不要求覆盖全部生活领域。

```
┌────────────────────────────────────────────────────────────┐
│  表现层 — 城市场景 + 数据面板（由已接入内容驱动）              │
├────────────────────────────────────────────────────────────┤
│  API 网关 — smartcity-gateway (:8080)          【平台】      │
├────────────────────────────────────────────────────────────┤
│  场景聚合 — smartcity-city-scene（汇总贡献）    【平台】      │
├────────────────────────────────────────────────────────────┤
│  内容模块（可独立扩展 / 可替换）                 【内容】      │
│  种子：traffic · parking · food · shopping · energy · env    │
│  候选：community · property · leisure · checkin · ranking    │
├────────────────────────────────────────────────────────────┤
│  注册中心 — Eureka (:8761)                     【平台】      │
└────────────────────────────────────────────────────────────┘
```

## 平台能力

| 能力 | 说明 |
|------|------|
| 场景承载 | `web/` 城市场景与状态表达 |
| 接入聚合 | `city-scene` 拉取各模块可视化贡献并合并 |
| 统一入口 | Gateway 路由 API 与静态资源 |
| 服务发现 | Eureka 注册与发现 |
| 空间约定 | 统一对象字段（id、module、坐标、status 等） |

## 内容模块（种子与候选）

| 分组 | 模块 | 角色 |
|------|------|------|
| 出行 | traffic, parking | 种子内容 |
| 消费 | food, shopping（leisure 候选） | 种子 / 候选 |
| 市政 | energy, environment | 种子内容 |
| 居住 | community, property | 候选内容（验证空间类接入） |
| 互动运营 | checkin, ranking | 候选内容（验证互动类接入） |

候选模块用于扩展平台验证，**不是**「必须做完才算产品成功」的清单。详见 [愿景](./01-vision.md)。

## 接入契约（内容如何挂上平台）

`city-scene` 拉取各模块 `/visualization/contribution`，合并：

- 片区 / 小区边界
- 廊道（交通、能源）
- 资产点（车场、门店、打卡点、设施）

详情请求按 `module` 路由；模块也可提供独立 API。新内容最少需：

1. 可注册的服务（或等价贡献源）
2. 符合约定的 contribution
3. 网关路由（若需对外详情）
4. 对象带空间字段与 status

## 数据流（种子内容演示示例）

以下是**已接入内容之间的联动示例**，不是平台必达的「全能生活闭环」：

```
点选商场（shopping）
  → 详情（客流）
  → 附近车场（parking）
  → 周边餐饮（food）
```

打卡、榜单等仅在对应内容接入后出现在路径中。
