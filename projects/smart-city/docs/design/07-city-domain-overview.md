# 城市业务域总览

城景是**平台**：城市底图与接入契约稳定后，各类城市内容（市政、出行、消费、居住、互动等）可以模块方式挂入。  
下表是**内容目录**（种子 + 候选），不是「必须自建完才算产品」的范围清单。愿景见 [01-vision.md](./01-vision.md)。

## 内容分层（可接入的槽位）

```
城市底图（区 / 街道 / 小区 / 商圈）     ← 平台
    ├── 出行：交通、停车                 ← 种子内容
    ├── 居住：小区、物业、设施           ← 候选内容
    ├── 消费：购物、餐饮、娱乐           ← 种子 / 候选
    ├── 互动：打卡点、足迹、评论         ← 候选内容
    ├── 市政：能源、环境                 ← 种子内容
    └── 运营：排行榜、热度、活动         ← 候选内容
```

未列出的品类（教育、医疗、文旅专题等）同样可按同一契约接入，不必先写进产品范围。

## 内容目录（现有 + 候选）

| 业务域 | 模块 | 状态 | 核心对象 |
|--------|------|------|----------|
| 交通 | `smartcity-traffic` | 种子 · 已有 | 信号灯、路段、摄像头 |
| 停车 | `smartcity-parking` | 种子 · 已有，待深化 | 停车场、车位、收费 |
| 餐饮 / 吃喝 | `smartcity-food` | 种子 · 已有，待深化 | 门店、菜品、排队、榜单 |
| 购物 | `smartcity-shopping` | 种子 · 已有，待深化 | 商场、店铺、客流、榜单 |
| 能源 | `smartcity-energy` | 种子 · 已有 | 变电站、充电桩 |
| 环境 | `smartcity-environment` | 种子 · 已有 | 空气、水位、噪声 |
| 小区 | `smartcity-community` | **候选** | 小区、楼栋、出入口 |
| 物业 | `smartcity-property` | **候选** | 工单、报修、公告、设施 |
| 玩乐 | `smartcity-leisure` | **候选** | 景点、场馆、夜生活点 |
| 打卡 / POI | `smartcity-checkin` | **候选** | 打卡点、足迹、徽章 |
| 排行榜 | `smartcity-ranking` | **候选** | 美食榜、购物榜、打卡榜 |

> 候选模块按同一微服务模板扩展即可，用于验证接入契约；也可由外部系统按 contribution 约定接入。详见 [06-spring-cloud-microservices.md](./06-spring-cloud-microservices.md)。

## 信息在城市中如何呈现

1. **接入上图**：内容模块贡献边界、廊道、资产点到城市场景。
2. **再看数据**：点击对象看到占用率、排队、评分、热度、近期事件（由该内容提供）。
3. **再做互动**：打卡、收藏、工单等由具体内容模块提供；未接入则不出现。

## 角色

| 角色 | 关注点 |
|------|--------|
| 城市运营者 | 已接入内容上的全局热力、异常、设施健康 |
| 内容提供方 | 按契约贡献对象与指标 |
| 物业人员 | 小区工单、设施巡检（候选内容接入后） |
| 商户 / 市民 | 各域能力随内容接入而可用 |

## 统一空间对象

所有城市事物尽量落到同一套空间模型：

| 字段 | 说明 |
|------|------|
| `id` | 全局唯一 |
| `module` | 所属业务模块 |
| `name` | 展示名称 |
| `category` | 细分类（如火锅 / 商场 / 地下车库） |
| `x` / `y` 或经纬度 | 可视化坐标 |
| `districtId` / `communityId` | 所属片区 / 小区 |
| `status` | online / warning / critical / offline |
| `tags` | 标签（亲子、夜宵、免费停车等） |
