# 项目周期编排

本文定义 Urban Lens / 城景（指挥城市）的交付阶段与优先级。  
总原则：**先平台、后内容；内容可多可少，平台契约优先稳固。**

技术细节以 `docs/design/` 为准。

## 编排原则

1. **平台大于清单**：不把「生活方方面面」排进必达范围。
2. **先看得见，再看得懂**：场景与空间对象优先于复杂运营配置。
3. **种子内容验证平台**：用 parking / food 等证明接入路径，再考虑候选域。
4. **候选内容择优接入**：community 等按验证需要或业务拉动上马，可延后可外部化。
5. **可演示优先**：每阶段结束须有可演示路径。
6. **边界清晰**：不做数字孪生仿真与闭环自控；不自建全能生活系统。

## 现状基线（周期起点）

| 类别 | 内容 |
|------|------|
| 平台 | Eureka、Gateway、city-scene、静态城市场景 UI |
| 种子内容 | traffic、parking、food、shopping、energy、environment |
| 待深化种子 | parking、food、shopping |
| 候选内容 | community、property、leisure、checkin、ranking |
| 文档 | 愿景已收束为平台叙事；`docs/pm/` 负责介绍与周期 |

版本口径：后端 Maven `0.1.0-SNAPSHOT`。

## 阶段总览

```
P0 平台基线 ──► P1 接入契约+种子深化 ──► P2 扩展接入验证 ──► P3 指挥体验打磨
   场景可跑           挂得稳、看得懂              候选/外部择一验证         态势与口径
```

| 阶段 | 主题 | 退出条件（DoD） |
|------|------|-----------------|
| **P0** | 平台基线 | 启停稳定；场景可加载；介绍口径为「平台 + 内容」 |
| **P1** | 契约巩固 + 种子深化 | contribution / 空间对象约定写清；parking+food（或 shopping）演示扎实 |
| **P2** | 扩展接入验证 | 至少一种「新内容接入」成功：自建候选模块 **或** 外部/模拟贡献源 |
| **P3** | 指挥体验打磨 | 异常状态表达统一；运营者识别路径清晰；文档与演示一致 |

> 原「居住全做 + 打卡榜单闭环」不再作为必达主线；它们是 P2 的可选验证项。

## 里程碑

| ID | 名称 | 阶段 | 交付物 |
|----|------|------|--------|
| M0 | 平台口径就绪 | P0 | 愿景 / 介绍 / 周期文档对齐「平台 + 可接入内容」 |
| M1 | 场景基线可演示 | P0 | start-all 稳定；UI + `/api/v1/city/scene` 可用 |
| M2 | 接入契约明文 | P1 | 贡献字段、status、详情路由约定可被新模块照做 |
| M3 | 种子内容可演示 | P1 | 停车 + 餐饮（或购物）状态与详情一致 |
| M4 | 扩展接入验证 | P2 | 一个候选域上图，**或** 等价外部/模拟 contribution 接入 |
| M5 | 指挥席最小可用 | P3 | 异常/告警视觉规范 + 运营者快速识别路径说明 |

可选加分（非门禁）：property 工单、checkin、ranking、leisure——仅在有明确拉动时排入 P2/P3。

## 优先级（执行序）

| 优先级 | 对象 | 阶段 | 理由 |
|--------|------|------|------|
| P0 | platform（registry/gateway/city-scene/web） | P0 | 平台本体 |
| P1-a | 接入契约文档化 + city-scene 稳定性 | P1 | 决定「能不能接各种各样的内容」 |
| P1-b | parking（种子深化） | P1 | 高价值示范内容 |
| P1-c | food 或 shopping（择一深化即可） | P1 | 第二路种子，证明多内容并存 |
| P1-d | traffic / energy / environment | P1 | 保活与聚合一致，不大改 |
| P2 | 任一扩展接入（community 推荐作空间类验证） | P2 | 验证「新槽位」；其余候选按需 |
| P3 | 状态视觉与指挥路径 | P3 | 平台体验，而非堆业务 |

## 每阶段工作包

### P0 — 平台基线

- [x] 愿景收束为平台叙事
- [x] 指挥城市介绍与本周期文档
- [ ] 启停与场景冒烟
- [ ] README 试用路径复核

### P1 — 契约 + 种子

- [ ] 明文 contribution / 空间对象 / 详情路由约定（可落在架构或微服务文档）
- [ ] parking 深化并对齐场景
- [ ] food 或 shopping 深化（不必两域同时做完）
- [ ] `mvn test` + 场景点选回归

### P2 — 扩展接入验证（二选一或更多）

- [ ] **路径 A**：新建一个候选微服务（推荐 community）走通模板
- [ ] **路径 B**：用模拟/外部贡献源证明非自建也可上图
- [ ] 记录接入步骤，回写设计文档，供后续内容复用

### P3 — 指挥体验

- [ ] 统一 status 视觉
- [ ] 运营者异常识别路径说明
- [ ] 介绍文档与演示终检（只宣称已接入能力）

## 依赖关系

```
platform (P0)
    └── 接入契约巩固 (P1-a)
            ├── 种子深化 parking / food|shopping (P1)
            └── 扩展接入验证 (P2，可选内容)
                    └── 指挥体验 (P3，平台侧)
```

## 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 愿景再次膨胀为「全能生活」 | 周期失控 | 变更先改愿景与本文；候选域默认非门禁 |
| 只堆业务、不稳契约 | 无法接外部内容 | P1 契约里程碑先于新域开发 |
| 种子与候选并行过多 | 演示破碎 | P1 种子择一深化；P2 只强制一种扩展验证 |
| 对外口径含候选域 | 预期失控 | 介绍只写已接入；候选标注「可接入」 |

## 协作与变更

| 事项 | Owner 口径 |
|------|------------|
| 愿景边界、介绍口径、阶段门禁 | 项目经理 |
| 接入契约与领域设计 | 设计 / 研发 |
| 平台与内容实现 | 对应模块研发 |

1. 调整「必达 vs 可选」：先改本文与愿景。  
2. 调整接口：先改 `docs/design/`。  
3. 对外话术：先改 [指挥城市介绍](./01-command-city-intro.md)。

## 与成功标准的映射

| 成功标准 | 最早里程碑 |
|----------|------------|
| 平台口径清晰，范围不膨胀 | M0 |
| 新内容可按契约接入 | M2、M4 |
| 种子内容可演示 | M3 |
| 运营者快速识别异常 | M5 |
